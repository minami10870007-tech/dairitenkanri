# 紹介者管理アプリ（Google スプレッドシート + GAS / Netlify）

紹介者と紹介案件を管理するシンプルなアプリです。データベースは Google スプレッドシート、
処理は Google Apps Script（GAS）。画面は2通りの使い方ができます。

| 使い方 | 画面 | 向いている場面 |
| --- | --- | --- |
| A. スプレッドシート内 | メニュー「紹介者管理 → アプリを開く」 | とりあえず自分だけで使う |
| B. Netlify に公開 | スマホ・PC のブラウザから URL で | 外出先やスマホから使う、複数人で使う |

```
[ブラウザ / スマホ]  ──fetch(POST)──▶  [GAS ウェブアプリ]  ──▶  [スプレッドシート「紹介者」シート]
 Netlify の静的HTML         合言葉で認証          doPost (Api.gs)        1件 = 1行
```

## スプレッドシートとの連携の仕組み

連携しているのは次の3本だけです。**データの同期やコピーは一切ありません**。スプレッドシートが
そのままデータベースで、アプリはそこに直接読み書きします。

| # | どこ ⇄ どこ | 何でつながるか | 設定する場所 |
| --- | --- | --- | --- |
| 1 | スプレッドシート ⇄ GAS | **同じファイルに属している**（コンテナバインド） | スプレッドシートの「拡張機能 → Apps Script」から作るだけ。設定不要 |
| 2 | GAS ⇄ Netlify の画面 | **ウェブアプリの URL**（`/exec`） | 画面の「接続設定」に貼る |
| 3 | 画面 → GAS の認証 | **合言葉**（スクリプトプロパティ） | メニューで発行 → 画面の「接続設定」に貼る |

```
スプレッドシート「紹介者」シート
        ▲
        │ ① 拡張機能から作ったスクリプトは、そのファイルを直接読み書きできる
        │    （SpreadsheetApp.getActiveSpreadsheet）
   Apps Script (Code.gs / Api.gs)
        ▲
        │ ② https://script.google.com/macros/s/.../exec  ← デプロイで発行される URL
        │ ③ {"action":"add","token":"合言葉", ...}       ← 合言葉が一致しないと拒否
   Netlify の index.html（ブラウザ・スマホ）
```

つまり「①はスプレッドシートからスクリプトを作った時点で完了」していて、あとから手で紐づける
作業はありません。**あなたがやるのは ② の URL と ③ の合言葉を画面に貼るだけ**です。

### 連携できているかの確認

- スプレッドシートのメニュー **紹介者管理 → 接続状況を確認**
  → 書き込み先のスプレッドシート名・シート名・件数・合言葉の発行状況が出ます。
- Netlify の画面のヘッダー
  → 接続できていれば「**〇〇（スプレッドシート名）に接続中**」と表示されます。
- 画面から登録して、スプレッドシートを再読み込み
  → 「紹介者」シートに1行増えていれば連携できています。

### 独立したスクリプトから使う場合（上級者向け）

スプレッドシートからではなく `script.google.com` から単体でスクリプトを作った場合は ① が
成立しません。その場合は Apps Script の **プロジェクトの設定 → スクリプト プロパティ** で
`SPREADSHEET_ID` に対象スプレッドシートの ID を設定してください。
（ID は URL の `https://docs.google.com/spreadsheets/d/【ここ】/edit` の部分）

### つまずきやすいところ

| 症状 | 原因と対処 |
| --- | --- |
| 「接続できません」と出る | デプロイの「アクセスできるユーザー」が**全員**になっていない |
| 「合言葉が未発行です」 | メニューの「外部連携用の合言葉を発行」を実行していない |
| 急に繋がらなくなった | 「新しいデプロイ」を作ると **URL が変わります**。デプロイを管理 → 編集 → バージョン：新バージョン で更新するか、新しい URL を画面に貼り直す |
| 「応答が JSON ではありません」 | URL が `/exec` で終わっていない（`/dev` や編集画面の URL を貼っている） |
| 「スプレッドシートが見つかりません」 | 独立スクリプトで作っている。上記の `SPREADSHEET_ID` を設定する |

## できること

- 紹介者の登録（紹介者名・電話番号・メール・被紹介者・ステータス・備考）
- 一覧表示と検索（紹介者名 / 被紹介者 / 電話 / メール / 備考 / ID の部分一致・即時）
- ステータスの絞り込みと、一覧上でのワンタップ変更（未対応 / 対応中 / 成約 / 見送り）
- 並び替え（新しい順 / 古い順 / 紹介者名順）と1件削除（確認ダイアログあり）
- 集計（合計、ステータス別、紹介者ごとの紹介件数・内訳）
- ダークモード対応、スマホ最適化（下部タブバー・カード表示）、オフライン時のエラー表示

データは「紹介者」シートに1件=1行で入るので、スプレッドシート側で直接編集・並べ替え・
フィルタ・ピボットテーブルも使えます。

## ファイル

| ファイル | 中身 |
| --- | --- |
| `src/Code.gs` | シートの読み書き・検索・集計、カスタムメニュー、シート内画面の表示 |
| `src/Api.gs` | 外部から呼ぶ JSON API（`doPost`）と合言葉の発行・検証 |
| `src/index.html` | スプレッドシート内で開く画面（簡易版。Netlify 版だけ使うなら不要） |
| `src/appsscript.json` | Apps Script のマニフェスト |
| `netlify/index.html` | Netlify に置く画面（fetch で API を呼ぶ版・1ファイル完結） |
| `netlify/_headers`, `netlify.toml` | Netlify のセキュリティヘッダーとキャッシュ設定 |
| `test/smoke.js` | シート操作ロジックのテスト（GAS API をスタブ化して Node で実行） |
| `tools/api-contract-test.mjs` | 画面 ↔ API の通信テスト（CORS・登録・更新・削除・エラー処理） |
| `tools/audit-ui.mjs` | UI 自動監査（レスポンシブ・タップ領域・コントラスト・アクセシビリティ） |

`npm test` は、シート操作に加えて `doPost` の認証・各 action・壊れたリクエストの扱いまで検証します。

## セットアップ A：スプレッドシート側（必須・5分）

1. Google スプレッドシートを新規作成し、**拡張機能 → Apps Script** を開く。
2. `コード.gs` の中身を全部消して、`src/Code.gs` を貼り付ける。
3. **ファイル → ＋ → スクリプト** で `Api` を作り、`src/Api.gs` を貼り付ける。
4. **ファイル → ＋ → HTML** で `index` を作り、`src/index.html` を貼り付ける
   （ファイル名は拡張子なしの `index`。`doGet` / `openApp` がこの名前で読み込みます）。
5. 保存して、関数一覧から `setup` を選んで **実行**。初回は権限の承認を求められるので許可する。
   → 「紹介者」シートが作られ、見出し行とステータスのプルダウンが設定されます。
6. スプレッドシートを再読み込みすると、メニューに **紹介者管理** が出ます。

ここまでで「A. スプレッドシート内で使う」は完成です（**紹介者管理 → アプリを開く**）。

## セットアップ B：Netlify に公開する

### B-1. GAS をウェブアプリとしてデプロイ

1. Apps Script エディタで **デプロイ → 新しいデプロイ → 種類：ウェブアプリ**。
2. 設定：
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
     （Netlify の静的ページから呼ぶには匿名アクセスの許可が必要です。代わりに
     **合言葉**で保護します。後述の「セキュリティの考え方」を必ず読んでください）
3. 表示された **`/exec` で終わる URL** を控える。

### B-2. 合言葉を発行

スプレッドシートのメニュー **紹介者管理 → 外部連携用の合言葉を発行** を実行し、表示された
文字列を控える（忘れたら「外部連携用の合言葉を確認」で見られます）。

### B-3. Netlify にデプロイ

**方法1：フォルダをドラッグ＆ドロップ**（いちばん簡単）

1. https://app.netlify.com/drop を開く。
2. この `netlify` フォルダをそのままドロップ。

**方法2：GitHub 連携**

1. Netlify で **Add new site → Import an existing project** からこのリポジトリを選ぶ。
2. Build command は空、Publish directory は `netlify`（`netlify.toml` に設定済みなので自動で入ります）。

ビルド工程はありません。`netlify/index.html` 1ファイルで完結していて、外部の CDN や
Web フォントも読み込まないので、初回表示も速く、オフラインの影響も受けにくい構成です。

### B-4. 接続する

公開された URL を開くと「接続設定」が出るので、B-1 の **URL** と B-2 の **合言葉** を入力して
「接続する」。以降はこの端末のブラウザに保存され、次回から自動で一覧が開きます。

> **デプロイを更新したとき**：Apps Script で「新しいデプロイ」を作ると URL が変わります。
> URL を変えたくない場合は **デプロイを管理 → 編集（鉛筆）→ バージョン：新バージョン** で更新してください。

### 動作を先に見たい場合

`https://あなたのサイト.netlify.app/?demo=1` を開くと、**デモモード**でサンプルデータを使って
一通り操作できます（スプレッドシートには何も保存されません）。

## セキュリティの考え方

- ウェブアプリのアクセス権を「全員」にするのは、静的ページから呼ぶために必要な設定です。
  そのままだと URL を知っている人は誰でも読み書きできてしまうため、**合言葉（トークン）**を
  知らないリクエストは `Api.gs` が拒否します。合言葉が未発行のときは全リクエストを拒否します。
- 合言葉は Netlify のページのソースには埋め込まれていません。利用者が初回に入力し、
  その端末の localStorage にだけ保存されます。
- 共有端末で使ったときは、歯車アイコン → **接続を解除** で消してください。
- 合言葉が漏れたと思ったら、メニューから再発行すれば古い合言葉は即座に無効になります。
- 顧客の個人情報を扱うので、リポジトリを公開する場合でも**スプレッドシートの URL や合言葉は
  コミットしない**でください（このリポジトリのコードには一切含まれていません）。
- さらに厳しくしたい場合は、Netlify 側にもパスワード保護（Site protection）や
  Netlify Identity をかけるのが有効です。

## 開発・検証

```bash
npm install          # playwright-core（検証用のブラウザ操作ライブラリ）

npm test             # シート操作ロジック + 画面↔API の通信テスト
npm run audit        # UI 自動監査（7種類の画面幅 × ライト/ダーク × 3画面 + ダイアログ）
npm run audit:shots  # 上記 + audit-out/ にスクリーンショットを保存
```

`npm run audit` は実ブラウザで次を機械的に検査し、1件でも違反があれば失敗します。

- 横スクロールが出ていないか / 要素が画面外にはみ出していないか / 内容が切れていないか
- タップ領域が 44×44 以上か、文字が 12px 以上か、入力欄が 16px 以上か（iOS の自動ズーム対策）
- 文字色と背景色のコントラスト比が WCAG AA（通常 4.5:1、大きい文字 3:1）を満たすか
  （グラデーション背景は色停止点すべてで判定）
- ボタン・入力欄に読み上げ用の名前があるか、見出し構造が妥当か
- 画面幅に応じて表 ⇄ カードが正しく切り替わるか、固定タブバーが本文を隠していないか
- 登録 → 一覧反映 → トースト表示までのフローが動くか

## データの列

| 列 | 説明 |
| --- | --- |
| ID | `R0001` 形式の自動採番。既存の最大値 + 1 なので削除しても重複しない |
| 登録日 | 登録した日時 |
| 紹介者名 | 必須項目 |
| 電話番号 / メール | 任意。一覧からタップで発信・メール作成ができる |
| 被紹介者 | 紹介された人・会社 |
| ステータス | 未対応 / 対応中 / 成約 / 見送り |
| 備考 | 経緯やメモ |
| 更新日 | 最後に更新した日時 |

## カスタマイズのヒント

画面は2つあります（`netlify/index.html` が本命、`src/index.html` はスプレッドシート内で開く簡易版）。
項目を増やすときは、使っているほうの画面だけ直せば十分です。

- **項目を増やす** → `src/Code.gs` の `HEADERS` に列名を追記し、`netlify/index.html` の入力欄と
  一覧の表示を同じ列名で追加する（検索対象にもしたい場合は `listReferrers` と
  `netlify/index.html` の `visibleRows` の検索キー配列にも足す）。
- **ステータスの選択肢を変える** → `src/Code.gs` の `STATUSES` を書き換えて `setup` を再実行する
  （画面側は API から選択肢を受け取るので、色の割り当てだけ `STATUS_CLASS` に追記すれば OK）。
- **紹介料や成約金額を管理する** → `HEADERS` に「金額」を追加し、`getSummary` で合計すると
  紹介者ごとの実績が出せます。
- **色を変える** → `netlify/index.html` 冒頭の `:root` にある CSS 変数（`--accent` など）を
  書き換えるだけで全体に反映されます。変更後は `npm run audit` でコントラストを検査できます。
